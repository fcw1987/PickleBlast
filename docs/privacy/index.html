PickleBlast Privacy

Last updated: October 6, 2026.

This policy describes the PickleBlast app, this GitHub Pages website, and the GitHub services used for support and security reports.

The app

PickleBlast gameplay runs locally on Apple Watch. There are no in-app accounts, ads, tracking, analytics SDKs, or developer-operated gameplay servers. The app does not access health, location, contacts, microphone, or camera information.

The app stores Digital Crown sensitivity, the haptics preference, the best Arcade score, and records for The Wall, The Banger, The Poacher, The Dinker, and The Lobber in its local storage. A match in progress is held in memory and is not restored after the app process ends. These settings and records are not sent to the developer.

Privacy and Support information are bundled with the app and can be read offline without signing in. Reading these pages does not load remote content. If you separately visit the website or use GitHub to send a report, the website and support sections below apply.

Managing local information

You can change Crown sensitivity and haptics in Settings. There is no in-app control to erase saved records. Deleting the app removes its local data container. Apple's backup and restore services may retain or restore app data under Apple's policies; deleting the app does not promise deletion of backups. PickleBlast does not keep a developer-operated remote copy of your settings or records.

Apple may process information through its operating system, App Store, backups, and optional diagnostic services under Apple's own policies. This policy does not claim that those services collect nothing. See Apple's privacy policy.

This website

GitHub hosts this website through GitHub Pages. The project adds no analytics, advertising, tracking scripts, external fonts, or account system to the site.

GitHub states that Pages logs visitors' IP addresses for security, including visits made without signing in. GitHub's processing is governed by the GitHub Privacy Statement. See also GitHub Pages data collection.

Support and security reports

Ordinary support uses GitHub Issues. Posting requires a GitHub account. Your username, issue text, and attachments are public and may be viewed or copied by others. Submit only the information needed to explain your question, bug, or suggestion. Do not include sensitive personal information, passwords, credentials, account details, serial numbers, device identifiers, or unredacted logs. Check screenshots before attaching them.

Security vulnerabilities should be reported through GitHub private vulnerability reporting, not a public issue. GitHub processes those reports through its service and makes them available to authorized participants. This route is for security concerns, not private general support.

The developer uses information you voluntarily submit to understand and respond to reports. GitHub controls its account, hosting, and reporting infrastructure under its policies. The developer cannot promise to erase GitHub's infrastructure logs, backups, or copies made by others.

Questions

For questions about PickleBlast or this policy, read the Support page or open a support question. Keep any public question free of sensitive information.
